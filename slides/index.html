SAY — "How many of you built your React app for users? Buttons, forms, wizards, dropdowns — all designed for a human with a mouse. What happens when your next user isn't a human?"
DO — start on the title, no bio.

Who is your user?

👤

Human

  • Reads text & labels
  • Clicks buttons
  • Fills forms
  • Waits for loaders
🤖

Agent

  • Reasons about intent
  • Calls tools
  • Acts, then checks the result
  • Never touches the DOM

Both are users. Only one has a mouse.

SAY — "Both want the same outcome. They just interface with your app completely differently."
The shift

Software is learning to act, not just answer.

  • Copilot, Claude, ChatGPT — and now agentic workflows.
  • Agents don't stop at a chat reply — they do things.
  • Your app's next user won't read your UI — it will call your capabilities.
SAY — "We're in an agentic wave. The apps we build are about to get a new kind of user."

The reframe

An agent is just another user.

Same capabilities. Two different interfaces.

👤 Human UI
wizard → server function
⚙️ One capability
validated by one schema
🤖 Agent UI
chat → tool call

The question: how do I build one app that serves both — without writing everything twice?

SAY — "This is the core idea of the whole talk. The agent is not a special case — it's just a different frontend."

SAY — "The most important design decision for agent users: what are they NOT allowed to do on their own?"
Patterns

Four patterns that fall out.

1 · Capabilities, not screens

Expose intent as functions, not pages.

2 · One contract

A Zod schema is the shared language for UI and tools.

3 · Human-in-the-loop

Gate irreversible / high-stakes actions by default.

4 · Observe the agent

Realtime, telemetry, cost — like any other user.

SHOW — flash capabilities.ts, schemas.ts, the approval UI, and the dashboard for each pattern.
Takeaways

Remember three things.

  • The next user may not be human — but it's still a user.
  • You already have the tools — server functions, typed schemas, React.
  • The agent doesn't replace your UI — it feeds it.
